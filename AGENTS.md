# AGENTS.md — plate

## What this is
"What's on my plate right now?" cockpit for Antonio (personal first, work later via the same code cloned from GitHub). **Files in open formats are the source of truth; the webapp is a thin view** that reads and writes them on every request (no cache, no database). Organizing unit: the **workstream**; items (tasks, tickets, PRs, sessions, conversations, notes) hang off workstreams, and the user classifies by dragging/moving, never by hand-editing properties.

Run (Node ≥ 18, **zero dependencies**):
```bash
npm start                      # node server.mjs → http://localhost:4173 (PORT=… to change)
PLATE_DATA_DIR=/path npm start # data folder; default is the Obsidian vault folder x/Plate (see store.mjs)
npm run collect                # todoist + github + sessions
npm test                       # node --test test/*.test.mjs (stub gh in test/gh-stub.mjs, scratch data dir)
```
**Restart gotcha:** the server loads routes at startup. After changing `server.mjs`/`lib/`, just run `npm start`: its `prestart` (`scripts/free-port.mjs`) stops a Plate server already on `PORT` (only if its command line runs `server.mjs`). Frontend changes (`public/index.html`) only need a reload. Preview tooling uses `.claude/launch.json` (config `plate`); if 4173 is busy it picks another port.

## After every pull (on any machine)
Read `CHANGELOG.md` and compare its entry numbers with `.plate-changelog-seen` (gitignored, at the repo root; one number). For each newer entry, do its **Setup** steps on this machine: tell the user what was added, ask for the values only they know (e-mails, vault and QuickAdd choice names) and write them into `<data>/sources.md`; then restart the server and write the newest number into `.plate-changelog-seen`. No marker file yet: check which Setup keys are already present in `sources.md` to tell what this machine already has, confirm with the user, then write the marker.
**When you change something that needs setup** (a new `sources.md` key, scope, login, env var, a removed/renamed view or key), add a numbered entry at the top of `CHANGELOG.md` with a Setup list, and document the key in README's Configuration table.

## Data model
Schema source of truth: **`README.md` in the data folder** (`$PLATE_DATA_DIR`, default `./data`; set it to your own data folder). Don't duplicate it here; read it before touching data code. Summary:
- `workstreams/<slug>.md` — YAML frontmatter + body. **Primary entity.** Tree via `parent` (one slug), graph edges via `related` (undirected), `state` active|paused|done, anchors `github: ["repo:owner/name", …]`.
- `items.jsonl` — one item per line, `source` ∈ `todoist | github | session | teams | link | note | ghref`; `workstream` = slug or `null` (Inbox). Moving an item rewrites only that field.
- `events.jsonl` — append-only log (`item.new`, `item.gone`, `item.moved`, `item.state`, `item.removed`, `workstream.new`, `workstream.reparented`, `todo.new`, `todo.done`, `todo.reopened`). Today's events feed the mindmap's Today mode; raw material for a future git-graph view.
- Item annotations set from the UI and never overwritten by collectors (they only assign the fields they pull): `alias`, `label`, `snoozedUntil` (`/api/item/update`, `patchItem`). A snoozed item is not "needs you" until then (events `item.snoozed`/`item.unsnoozed`).
- `applyRules()` (store.mjs): routes Inbox items by a workstream's `repo:` anchor and anchored sessions by their PR's workstream; called after every collector run (in `runOne`), on `/api/collect`, on `/api/ws/update` with `github`, and `/api/rules/apply`. Epic (`issue:`) anchors still only apply at creation (they need the live parent chain). It routes closed/merged items too (a known merged PR belongs to its repo's workstream). `repoAnchors()` = lowercase repo → slug, shared by the rules and the GitHub collector.
- "Needs you" is derived in `lib/store.mjs` (`needsYou`): open Todoist due ≤ today, sessions in state `waiting` or with `turn: me` (not archived), open PRs with `reviewMe` (direct review request), tickets with new `activity` (someone else's comment/review newer than the item's `activitySeen`); never a `dismissed` item. The focus view also puts PRs with a "review" Status there.

## Layout
- `server.mjs` — stdlib `http` server, JSON routes (`/api/state`, `/api/move` (one `id` or `ids[]`), `/api/ws/create|update`, `/api/ws/todo` (tick, by checkbox index + text guard), `/api/ws/todo/add`, `/api/items/add|add-teams|add-github|remove`) + static `public/`. `/api/state` also carries today's `events`, `people` (sources.md login → e-mail) and `contacts` (mini-CRM: the workstreams' `people:` resolved against the people notes by `readContacts`). `/api/items/add` dedupes by url and answers `{existing, workstream}`.
- `collectors/tasknotes.mjs` — TaskNotes plugin tasks (`source: tasknotes`, kind styled like Todoist) from `tasknotes_dir`/`<data>/../TaskNotes/Tasks`, read-only; open ones only, a finished one only if already known (→ `done`). Workstream by `projects:` matching a workstream's name/`project:`; `due` (else `scheduled`) ≤ today = needs you.
- `lib/store.mjs` — all file IO (items, events, workstreams with a tiny frontmatter parser/patcher), validation (`BadRequest` → HTTP 400), cycle guard for `parent`. `addGithubItem` on an issue also adds the open/merged PRs that close it (live GraphQL) to the same workstream, or moves them there from the Inbox. To-dos = `- [ ]` lines in the workstream body. `readSources()` returns `{github_projects: [], people: {}}` when sources.md is missing.
- `lib/upsert.mjs` — shared collector upsert.
- `lib/log.mjs` — `log.info|warn|error` (timestamped, stdout + `.cache/plate.log`, rotated at 1 MB) and `tail()`; the server logs every write, error and read slower than 1 s (not the 20 s `/api/state` polls), collectors log their duration, the lock logs who holds it. `GET /api/log`.
- Settings: `SETTINGS` (store.mjs) = the sources.md keys the ⚙ drawer edits (`GET|POST /api/settings`, `patchSources` edits lines in place, empty removes the key; mappings like `people:` stay in the file). A new sources.md key = add it to `SETTINGS` (with `group`, `def` = the default shown in the drawer, `help`) and the README table; the drawer is how he remembers which keys exist, so never leave a key out.
- `lib/schedule.mjs` — in-server collector scheduler (child processes, one at a time) and `withLock`: **every POST handler is serialized with the write lock, and so is every cheap local collector run (devin, tasknotes)**; the network ones (`net: true`: github, mine, reviews, todoist) run OUTSIDE the lock, one at a time among themselves (`collectChain`), and take the lock only for `applyRules` afterwards: they held it 5-10 s and every UI write queued behind them ("server busy"). Their writes to `items.jsonl` are one synchronous read-modify-write at the end of the run (atomic rename), so the race with a drag is a window of milliseconds, never the fetch. (`busy` in `/api/state` says what holds it; a waiter >5s logs it; collectors are SIGKILLed at 120s and abandoned at 130s, since grandchildren like `gh` can keep the pipes open), because collectors rewrite `items.jsonl` whole (see above for the network ones). Running a collector by hand while the server is up bypasses the lock (small race with a drag). `/api/collect` = Sync now; `/api/state` carries `collect` status. **Devin watch:** `fs.watch` on the directory of `sessions.db` (only `sessions.db` and `-wal` events) runs the Devin collector 3 s after the last change, at most every 15 s (`devin_watch: off`); the 1-minute beat stays because idle → `waiting` is time, not a file change. `/api/collect {only: [...]}` runs a subset (the `r d` / `r g` keys). `collect: off` in sources.md stops the timers only (Sync now still works); `PLATE_NO_SCHEDULE=1` skips them for one run.
- `lib/devinrun.mjs` — `/api/devin/close {url}` ("O que falta?", any issue/PR; `devin_close_prompt`/`devin_close_model`; runs keyed `close:<url>`, session alias `Fechar: …`) shares `startRun` with `/api/devin/review {url}`: runs `devin -p "/code-review <url>"` (prompt: `devin_review_prompt`, `{url}` placeholder) in `devin_review_dir` from sources.md, in the background; `runs` in `/api/state`; logs in `.cache/devin-runs/`. The new session is anchored to the PR as soon as it appears (polled every 4 s while the run is going, plus once more on exit), which also routes it to the PR's workstream. Needs the CLI logged in (`devin auth login`; the Desktop login doesn't carry over). A non-zero exit **after the session exists** (a tool call rejected by a pre-hook) keeps the run `done` with `warn: true`; only a run with no session is `failed`. `linkSession` matches the folder by real path (else the only session born in the run window). The rename is Plate's alias only: the CLI has no rename. Binary: `DEVIN_BIN` / `devin_bin`, else the Devin.app bundle, else `devin` on PATH.
- `lib/devintranscript.mjs` — `/api/devin/transcript?id=`: walks `message_nodes` from the session's `main_chain_id` in `sessions.db`, user/assistant text only. Frontend: `openTranscript`. `startReview(url, model)`: `--model` from the UI box or `devin_review_model`.
- `lib/ghcontext.mjs` — `/api/gh/context?url=`: one issue/PR with parent chain, sub-issues, siblings, blockedBy/blocking, linked PRs (live GraphQL). Frontend: the drawer (`openCtx`).
- `collectors/*.mjs` — see below. `.cache/` (gitignored) holds dumps; it is personal data.
- `public/index.html` — the entire frontend (CSS + JS inline). Views: **Workstreams** (landing: mindmap → click a node → full-area focus view of one workstream) with the **Inbox panel** on the left (the old Triage list: search, Inbox/All open, kind filter, multi-select, type-ahead bulk move bar; dismiss (`d`, row ✕, scope "Dismissed" to restore: `/api/dismiss`, flag `dismissed` that collectors keep and a move to a workstream clears), review requests grouped first; drag a row, or the selection, onto a map node, onto a focused workstream's header or onto its child chips), and **Needs you** (flat list). Board and Triage views were removed 2026-10-26 (the panel replaces both). **Top 3 of the day** (`focus.jsonl`, `readTop3`/`setTop3`/`readTop3Prev` in store.mjs, `POST /api/top3 {type: ws|item, ref, on}`, `/api/state` has `top3` + `top3Prev`): a strip above the Workstreams/Needs-you views; pin with the right-click menu on any element carrying `data-pin="ws:<slug>"`/`"item:<id>"` (nodes, cards, Inbox rows, the focus header). Max 3, manual only; empty slots say so, and while any is free yesterday's (last day with pins) still-open pins show as faded ghost cards, click = pin for today, `carry all`. Pins are links, so a pinned thing that gets done shows struck through. **Bell** (`#bell`, `collectNotes`): corporate browsers block desktop notifications, so new waiting sessions, review requests, ticket activity and finished Devin runs are also diffed on each render into a per-browser list (`plate.notes`, 40); count on the bell, panel on click, nothing pops up (the browser `Notification` still fires when allowed). **Nesting** (`nestOf`, focus view only): a session under its anchor PR/issue and a PR under the issue in its `closes`, same workstream; `groupItems` places a stack by its most urgent member; `NESTED` suppresses the parent's redundant session chips. **Top 3 ✓**: a pin can carry `done: true` (`POST /api/top3 {type, ref, done}`). `teamsAuthor`: chip with a Teams deep link to the PR `author` (collected by github/mine/reviews) once a review ran. "Recently done" drops items older than `done_days`. Map extras: **idle** workstreams (`idleInfo`: active, something open, no event for `stale_days`, default 3; `/api/state` carries `activity {last, since}` from `events.jsonl`) are dimmed with an `Nd` badge; Today mode lights the path from each touched workstream up to its root too (dimmer, `path: true` in `todayHeat`); hovering a node lights the path up to the center plus its children and related (`wireNbhd`, edges carry `data-a/data-b`); **⌘/Ctrl+K** palette (`openPal`) jumps to a workstream or item (accent-insensitive); a workstream created from the map is centered once and pulsed green with a `new` tag for 8s (`freshWs`); Today mode has a D/W/M span (`/api/events?from=&to=`, heat adds up over the window, timeline capped at 300). Map camera: wheel/pinch = zoom at the cursor, drag the background = pan, double-click or **Fit** = refit (`cam` in the frontend, a CSS transform on `.canvas`; kept across re-renders; fit never goes below 0.4, pan reaches the rest). The `☑ n` button on a node fans its open tasks (Todoist/TaskNotes items + `- [ ]` body to-dos, max 8 + "+N more") out as leaves; the expanded set is a per-browser pref (`plate.tasksOpen`). Needs-you on the map: amber ring pulsing on nodes, and on the center hub for Inbox items that need you. Smart paste (Cmd+V outside a form field) adds an item: Teams link → `teams`, other single URL → `link`, else `note`; target = focused workstream or Inbox; undo toast. Pasting something already on the plate while a workstream is open offers "Move to <it>". Keys: `r d` / `r g` / `r a` = sync Devin / GitHub / everything now (chord within 1.5 s), `1`–`2` switch views, `i` toggles the Inbox panel, `/` = its search, `a`/`m`/`Esc` = select all / move / clear, `t` = Today mode on the mindmap (lit nodes + timeline of today's events; ← date → picks a past day through `/api/events?day=`, only days that were recorded have events). Branch colors hash the root's slug (stable when nodes are added; `color:` in the .md overrides). PR kind color follows GitHub: open green, merged purple, closed red (`ghState` from the collector, `status` for ghref). Focus view: "+ Meeting note" opens `obsidian://quickadd?vault=…&choice=<meeting_quickadd>&value-<var>=…` (sources.md `meeting_values`, placeholders `{workstream}` `{project}` `{slug}` `{date}`; workstream `project:` overrides the name); QuickAdd prompts for unnamed variables like the title. Built against the URI docs, not run against the work vault's choice. Ticket drawer: "Teams chat" builds a `teams.microsoft.com/l/chat/0/0?users=…&topicName=…&message=…` deep link (msteams:// + web), people = author + assignees via `people:`; untested against a real tenant.

## Note-backed workstreams (2026-11-02)
`note: "[[Name]]"` in `workstreams/<slug>.md` makes the workstream point at a vault note instead of duplicating it (`lib/store.mjs`: `findNote`, `searchNotes`, `workstreamFromNote`, `noteBody`). Notes are found by file name anywhere under the vault root (two levels above the data folder; dot-folders skipped; index cached 15 s, rebuilt after 2 s on a miss). `readWorkstreams` replaces `body` with the note's: its first 600 characters of text + **every** checkbox line, in file order, so the frontend's to-do indexes still match the file; `setTodo`/`addTodo` write into the note (`splitFile` returns the target `file`; a note without frontmatter is fine). A missing note → `noteMissing: true` (red chip), the workstream's own body is ignored. Create: ⋯ menu / ⌘K "Make a note a workstream…" (`openNotePal`, `GET /api/notes?q=`, `POST /api/ws/from-note {note, parent}`; goes under the focused workstream, an existing one is returned instead of a duplicate), or the "Note" field under Edit workstream (`/api/ws/update {note}`, empty unlinks). The focus view has an "Open note" button (`obsidian://open`, vault from `obsidian_vault`, `/api/state.vault`). The workstream file's own frontmatter/people/anchors work as usual. Tested in `test/notews.test.mjs`; the Obsidian side (Linter rewriting the note while Plate writes a checkbox) is not exercised.

## Local network access
**macOS firewall:** it blocks incoming connections to `node` (the phone gets "can't be reached"; seen 2026-11-01). Allowing the Homebrew `node` would open every node server on the machine, so `scripts/private-node.sh` makes `.bin/node/bin/plate-node` (private copy + `libnode` dylib, gitignored) and prints the `socketfilterfw --add/--unblockapp` line for that path only; `scripts/start.sh` (`npm start`) uses the copy when it exists. The `sudo` is the user's, never ours. Re-run the script after a node upgrade.
`lib/lan.mjs` + the top of the request handler in `server.mjs`. Default: listens on `127.0.0.1`. `lan: on` (read at startup) listens on `0.0.0.0` and every request not from loopback needs the token (`.cache/lan-token`, `?t=` once → `plate_t` cookie, HttpOnly/SameSite=Strict, then a redirect to the clean URL; otherwise 401 and a `lan: refused` log line). Static files and `/api/*` are both behind it; `/api/lan` (loopback only) gives the URLs with the token, shown in ⚙ with a QR code (vendored `public/vendor/qrcode.js`, qrcode-generator 1.4.4, MIT, no build step). Unit-tested (`test/lan.test.mjs`); **not exercised from a real phone** (in the build session the curl to the Mac's own LAN IP got an empty reply and the server logged nothing, cause unknown: test from the phone).

## Build conventions
- **Vanilla HTML/CSS/JS only. No framework, no build step, no npm installs.** It must stay cloneable onto a locked-down corporate machine.
- Keep changes narrow: frontend work lives in `public/index.html`, server work in `server.mjs` + `lib/`. Don't break existing routes, collectors, or drag-persist.
- Don't hand-edit the vault data to make UI changes work; test against a scratch copy (`PLATE_DATA_DIR=<copy> PORT=4180 node server.mjs`) so real data and the user's running :4173 server stay untouched.
- Don't commit or push unless asked. Don't touch the vault outside `x/Plate/`.
- Every item `url` is only rendered as a link if it is `https?://` or `msteams://`.

## Gotchas
- **A standalone script cannot call MCP connectors** (Todoist etc.). Collectors read a JSON dump in `.cache/*.json` (produced inside an agent session via the MCP, or by a CLI) or hit the service REST API with a token env var.
- **Manual sources (`teams`, `link`, `note`, `ghref`) have no collector.** `upsert(source, …)` only marks items of *its own* source `gone`, which is what keeps manual items safe. Any new manual source must have no collector, be added to `MANUAL_SOURCES` in `lib/store.mjs` (and `MANUAL` in the frontend), and never be fed through `upsert`. After touching `upsert.mjs`, verify a full `npm run collect` leaves manual items intact.
- **Collectors preserve `workstream`** (drags win); an incoming `workstream` is applied only when the item is first created.
- **Devin session state** (`collectors/devin.mjs`): archived → `done` (and hidden from the workstream view and its counts, review chips included); idle ≥ `devin_waiting_minutes` (default 2) → `waiting` (needs you); `turn: me` when the last message of the main chain is Devin's text with no tool call. The browser tab title carries the Needs-you count; clicking the Needs-you tile allows desktop notifications for sessions that start waiting.
- **Review button** is keyed on the url (`/pull/`), not `kind`: a pasted draft PR is `kind: draft`.
- **Creating:** `/api/tasks/create` writes a TaskNotes-format file (`createTask`), `/api/people/create` a person note (`createPerson`, never overwrites); both then rely on the tasknotes collector / the `people` patch. **Schedule** (`lib/schedule.mjs`): one 20s heartbeat, per-job interval `<name>_every_minutes` (sources.md) > `PLATE_EVERY_<NAME>` > default (devin 1, github 10, reviews 10, tasknotes 5, todoist 15).
- **People directory:** `lib/directory.mjs` finds a user by e-mail with `dscl <node> -search /Users EMailAddress|dsAttrTypeNative:mail|…`, then `-plist -read` of RealName/JobTitle/Department/Company (standard names, then the raw AD ones) through `plutil`; photo = `<data>` of `JPEGPhoto`, saved to `<vault>/x/Attachments`. The note's properties are the store (`createPerson`/`patchPerson`: role, department, company, email, teams, photo, directory_synced); the lookup never blocks creating a person. Only stub-tested.
- **Mini-CRM:** workstream `people: ["[[Name]]"]` (read as plain names, written back as wikilinks); the focus view's People row adds/removes them.
Two collectors share `source: session`** (`devin.mjs` owns `tool: devin`, `sessions.mjs` the rest); `upsert`'s `owns` keeps one from marking the other's items `gone`.
- **Devin Desktop deep links:** `devin://cascade?prompt=…` only focuses the window on the open session (old editor UI handler); there is no link that starts a new session with a prompt. Triggering a Devin skill on a PR has to go through the CLI (`devin -p "/skill …"`).
- **Desktop 3.4.27 vs `sessions.db`:** if a newer Desktop/CLI migrated the DB (schema V20), the older Desktop logs `migration V17..V20 is missing` and answers `Invalid params` to a session link (seen 2026-10-27; so "click opens nothing"). Use the transcript drawer, or keep one Desktop version per machine.
- **Devin asking you (approval/question):** `sessions.db` can't tell a session stopped on a command approval from one running a tool. The Desktop can: `windsurf.acp.metadataCache` (same `state.vscdb`) lists `sessions[]` with `isWaiting: true` for it (seen 2026-11-02 on a Cascade session asking to run `mkdir`). `collectors/devin.mjs` (`liveSessions`) turns that into `state: waiting`, `turn: me`, `asking: true` at once (no `devin_waiting_minutes` delay), and also **lists Cascade-provider sessions that exist only in that cache** (`provider: cascade`, `url: null`: no deep link is known for them). **CLI sessions (`devin` in a terminal) are not in that cache** and sessions.db shows nothing different for them (last node = assistant with tool calls, no result, `tool_call_state` empty, the row's `main_chain_id` can lag: the collector uses the last `node_id`). Their only signal is the CLI process's log, `~/.local/share/devin/cli/logs/devin_<stamp>_<pid>.log`: `Permission decision for tool <name>: prompting user` (no session id in the line); `session_locks/<session>.lock` holds the pid. `promptingUser` = last node has tool calls + pid alive + a prompt line at/after the session's last activity (±2 s) → `asking`. Heuristic from one observed `request_scope` prompt (2026-11-02): an `exec` approval or a Desktop-hosted `devin acp` process (one log, several sessions) is unverified, and a prompt answered in a way that saves nothing leaves it asking until the process dies. The cache is only as fresh as the Desktop's last write: if the Desktop is closed/crashed while a session asked, `isWaiting` can stay stale; `state.vscdb` isn't watched (the 1-minute beat catches it). Tested with a fake cache; the real read was verified against the live Desktop DB.
- **Devin store:** `devin list` only lists the current directory and stops at 50, so `collectors/devin.mjs` reads `sessions.db` read-only. Archiving is **not** in `sessions.db` (`hidden` stays 0): Devin Desktop keeps it in its own `User/globalStorage/state.vscdb` (table `ItemTable`), in two generations that the collector reads together: current = key `windsurf.acp.session/archivedSessions` → JSON array of refs `"acp/devin-cli/<id>"`; legacy = key `devin.desktopShell.localSessionAnnotations.<org>` → `{"devin-acp/devin-cli/<id>": {archived, done, folder, parent}}`. Malformed or missing data only means "nothing archived" (never a crash); covered by `test/devin.test.mjs` (runs the collector against a scratch DB). Deep link depends on the Desktop generation, set by `devin_link` in sources.md: `shell` (default) = `devin://app/return/<base64url of /sessions/<encodeURIComponent("acp/devin-cli/<id>")>>`, verified on Desktop 3.11 (there the acp form answers "This session doesn't exist"); `acp` = `devin://acp/session?sessionId=<id>&connectorId=devin-cli`, for older Desktops (3.4.27, the work machine's version, has no shell route; acp verified on it 2026-10-26). Cloud links still use the acp form, untested.
- **Frontend loads keyed on the server's answer loop forever on an old server.** Mindmap's span window (`winReady`) compares `dayData.to`; a server that predates `from`/`to` (not restarted) answered without it and every render re-fetched (seen 2026-10-28). Set the key client-side (`loadWindow` does) whenever a render triggers a fetch.
- **Rewriting `workstreams/<slug>.md`:** edit frontmatter lines in place (`patchFrontmatter`), keep the body and unknown fields (Obsidian adds `created`/`modified`). Never regenerate the whole file. `parent:` is written bare when root. Renaming changes `name` only; the slug/filename is stable.
- `related` is undirected but stored one-sided; unlinking removes the back-reference too.
- **GitHub live route** needs `gh auth refresh -s read:project`; without that scope use the dump route.
- **Tests that import `lib/log.mjs` or `lib/devinrun.mjs` set `PLATE_CACHE_DIR`** to a scratch folder, or their lines and run logs land in the real `.cache/` (`test/devinrun.test.mjs`).
- The frontmatter parser is minimal (scalars, inline lists, block lists, simple mappings), not full YAML.

## Design system ("cinematográfico funcional")
Dark, calm, one accent. All values are CSS custom properties on `:root` in `public/index.html`; reuse them, don't hardcode.
- **Surfaces:** `--bg #07100f` with two ambient radial glows (`--bg-glow-1` green, `--bg-glow-2` amber) on `body`; translucent layers `--surface / --surface-2 / --surface-3` (white at 3.5/6/9%), hairlines `--line` / `--line-2`. Glass panels use `backdrop-filter: blur`.
- **Text:** `--text`, `--text-2`, `--text-3` (primary → muted).
- **Accent is reserved for "needs you / waiting":** `--accent #ffa56e`, `--accent-soft`, `--accent-line`, `--accent-ink`. Never use it for decoration. Other semantics: `--late` (overdue), `--today`, `--live` (running).
- **Kind colors** (card stripe + kind label via `--k`): `--todo` Todoist, `--pr`, `--issue`, `--sess` session, plus teams `#9db4ff`, link `#7fd0e0`, note `#d9c79a`. New kinds need a `.card.k-<kind>` rule, a glyph in `GLYPH`, and a label.
- **Type & rhythm:** `--fs-xs 11 / sm 12.5 / md 14 / lg 17 / xl 24 / 2xl 34`; system UI font, `--mono` for refs. Spacing `--s1…--s6` = 4/8/12/16/24/32; radii `--r-sm 8 / md 14 / lg 20`. Generous padding, few borders.
- **Chrome:** top bar (brand/view name, clock, date, stat tiles; the "needs you" tile turns amber when > 0). Bottom **dock** (`nav.dock`, floating glass pill) is the only navigation: Workstreams · Needs you (amber pip with count). Add a view by adding a dock button + a render function in the `render()` map (and a `VNAME` entry).
- **Components:** `.card` (left kind stripe, kind row with glyph, title, `.chips`), `.chip` (`.dim`, `.need`, `.late`, `.today`), session `.state` pill with pulse for running, `.ipanel` + `.trow` (Inbox panel rows), `.wnode` (mindmap node, amber pulsing ring when it has needs-you), `.fsec` (focus-view section; `.need` variant has the amber frame), `details.props` for secondary forms, `.toast` (neutral, bottom-right stack in `#toasts`, `.err` red only for errors; `toast(msg, undo, label, kind)` / `toastErr`).
- Respect `prefers-reduced-motion`; keep animations short (≈.3s).
